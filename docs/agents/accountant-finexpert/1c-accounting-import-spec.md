# Ваш Финэксперт — импорт бухгалтерских отчётов 1С (ТЗ v0.1)
Дата: 2026-11-22. Статус: проектная спецификация, не реализовано.
Связь: docs/agents/accountant-finexpert/financial-passport-spec.md.
**Этап 1 — только бухгалтерский учёт.** Управленческий учёт, УДДС, бюджетирование, управленческие ОПиУ и баланс — следующий отдельный этап.

## Цель
После регистрации и создания «Финансового паспорта предприятия» клиент выбирает конфигурацию 1С, задачу и период. Система объясняет, какие именно отчёты нужны и зачем, даёт актуализируемый help по версии/конфигурации, принимает файлы, проводит структурную валидацию и предлагает бухгалтерский анализ с прослеживаемыми выводами.
Не требовать выгрузку всей базы, логины 1С или пароль. Только минимально необходимые отчёты.

## Поддерживаемые конфигурации и адаптеры (целевые, не реализованы)
- 1С:Бухгалтерия предприятия 8, разные редакции и варианты интерфейса.
- 1С:ERP Управление предприятием (контур регламентированного учёта).
- 1С:Комплексная автоматизация; 1С:Управление холдингом/ERP Управление холдингом.
- Другие конфигурации: универсальный адаптер с предпросмотром и ручным сопоставлением колонок.
На входе получать точное имя конфигурации, редакцию/версию, используемую организацию, период, признак БУ/НУ/управленческого контура, валюту и единицы измерения. Не обещать универсальной совместимости без теста.

## Матрица задач и минимально нужных данных
A. Общая диагностика: **обязательно** полная ОСВ по БУ за период (сальдо Д/К на начало и конец, обороты Д/К); **по доступности** бухгалтерский баланс и отчёт о финансовых результатах за сопоставимый период.
B. Дебиторская/кредиторская задолженность: общая ОСВ, затем ОСВ по сч. 60, 62, 76 с аналитикой по контрагентам/договорам; при необходимости карточка/анализ конкретного счёта. Детальные персональные данные исключать, если не нужны.
C. Финансовые результаты: общая ОСВ + отчёт о финансовых результатах; при расхождениях анализ 90, 91, 99 и по необходимости закрытие 20, 23, 25, 26, 44.
D. Проверка ошибок: общая ОСВ, затем адресный запрос карточек счетов/отчётов по проводкам для выявленных аномалий. Не собирать все проводки «на всякий случай».
E. Проверка конкретного счёта: ОСВ по счёту и/или карточка выбранного счета.
ОСВ является учётным регистром, а не годовой обязательной бухгалтерской отчётностью; отчёты могут иметь настройки группировки и детализации. Из одного отчёта нельзя гарантировать корректность всего учёта.

## Приём файлов
Приоритет XLSX; дополнительные конвертеры XLS, CSV, XML при наличии машиночитаемой схемы; PDF только с предупреждением об ограниченной точности. Никаких макросов/скриптов из файлов не исполнять. Максимальный размер, количество файлов, антивирус, защита архивов, таймауты, квоты — параметры CRM.
Каждый импорт: tenant, org_id, inn, period_start/end, accounting_kind=BU, 1c_configuration, edition, upload_time, uploaded_by, file_sha256, file_type, source_file_id, data_version.
Заголовки, итоги, объединённые ячейки, многострочные наименования, колонки дебет/кредит и субсчета распознавать адаптерами. Не принимать ошибочно УПРАВЛЕНЧЕСКИЙ регистр за бухгалтерский (особенно в ERP).

## Пайплайн
1. Пользователь выбирает задачу, период, организацию и конфигурацию.
2. UI генерирует минимальный перечень файлов и инструкции; поясняет назначение и ограничения обработки.
3. Защищённая загрузка и проверка типа/антивирус; временное хранилище.
4. Сопоставить ИНН, название, период и вид учёта с финансовым паспортом; при несовпадении не объединять автоматически.
5. Распознать табличную структуру; показать экран предпросмотра/маппинга и предупреждения.
6. Валидировать сальдо, итоги, обороты и внутренние арифметические равенства с учётом настроек отчёта, корректных знаков и округления. При неполной детализации выводить предупреждение вместо ложной ошибки.
7. Детерминированный расчёт и контроль сопоставимости периодов. Документный ИИ только классифицирует спорные поля и объясняет расчёты; первичные данные и правила сохраняются отдельно.
8. По выявленной проблеме запрашивать только необходимый второй файл (ОСВ по счёту, карточка или проводки). Не требовать весь набор сразу.
9. Отчёт: что проверено, что не проверено, найденные отклонения, суммы, ссылки на файл/лист/строку, гипотеза причины, рекомендация и пометка «требует проверки бухгалтером».
10. Удаление/хранение исходников по политике, экспорт результата и аудит действий.

## UX — понятное пояснение перед загрузкой
«Для анализа бухгалтерских данных нам нужна оборотно-сальдовая ведомость за выбранный период. Она показывает остатки и движения по счетам. С её помощью можно проверить арифметические равенства, динамику задолженности и другие признаки ошибок. Если обнаружатся расхождения, система попросит дополнительную карточку конкретного счёта. Не загружайте всю базу 1С; убедитесь, что выбранная организация и период верны. Анализ не исправляет записи в 1С и не является сдачей отчётности».
Перед обработкой показать сведения о хранении, сроках, доступе и согласиях; для ПДн обеспечить законное основание и минимизацию, не полагаться лишь на checkbox.

## Codex и ИИ
Стандартный импорт выполняют детерминированные парсеры + структурная модель для неоднозначных заголовков. Codex — ТОЛЬКО второй специализированный контур для сложных файлов и проверяемых программных аналитических операций в sandbox, без доступа к секретам/внешним платежам, под логированием. Не считать Codex универсальным OCR.

## Security & tenancy
Tenant isolation; организация должна быть подтверждена; права руководитель/бухгалтер/партнёр. Файлы доступны только авторизованной организации и её уполномоченным лицам. В журнал: источник, версия, период, владелец, статус, ошибки. Никаких персональных документов/финансовых файлов в GitHub. Защитить от formula injection при экспорте и внешних ссылок при обработке таблиц; отключить внешние формулы и макросы.
Не отправлять бухотчётность/не делать исправления в 1С автоматически.

## Критерии приёмки / тест-кейсы
- Тестовый XLSX ОСВ разных типов заголовков и периодов.
- Пример БП 3.0 и ERP регламентированный учёт; допустимость остальных конфигураций только после эталонных тестов.
- Неправильный ИНН, период, пустой файл, некорректные столбцы, отчёт по управленческому учёту вместо БУ.
- Итоги и сальдо с округлением, отрицательные суммы, субсчета, объединённые ячейки, неотражённое закрытие периода.
- PDF скан: ограниченная достоверность, обязательное подтверждение.
- Нет дополнительного отчёта: диагностика ограничена, не выдумываем детали.
- Попытка межарендного доступа/загрузка с макросами/формульными ссылками: отказ.
- Отдельное тестирование логики без реальных финансовых данных.

## Roadmap
M1: подтверждение реальных примеров из нескольких 1С, определение JSON канонической схемы и схемы импорта.
M2: экран помощника загрузки и help для БП 3.0/ERP; парсер XLSX, preview и тесты.
M3: отчёты по ОСВ и объяснимые проверки, адресные запросы детализации.
M4: расширение совместимости, пилот на согласованных обезличенных данных; безопасность, стоимость и качество.
M5: только после пилота — релиз под контролем.
Управленческий контур получает СОБСТВЕННОЕ ТЗ, отдельный список источников и пошаговый manual после завершения бухгалтерского этапа.
