# Подтверждённая связка «директор — организация — бухгалтер» в MAX

Утверждено пользователем 2026-11-22. Коммерческий бренд: «Ваш Финэксперт». Внутреннее имя «Кирюша» в публичном UI не использовать.

## Сценарий
1. Директор входит через MAX, создаёт «Финансовый паспорт» компании по ИНН/ОГРН. ЕГРЮЛ подтверждает сведения об организации, но не личность входящего директора. До первого назначения полномочий система обязана проверить, что пользователь MAX действительно уполномоченный представитель (проверяемый способ подтверждения личности/полномочий, при необходимости ручной workflow).
2. Директор вводит телефон бухгалтера, устанавливает срок и конкретные полномочия (загрузка, чтение очищенных документов, запуск анализа, чтение отчётов). По умолчанию доступ к оригиналам и делегирование третьим лицам запрещены.
3. Создаётся приглашение с одноразовым криптографическим токеном и TTL. Номер телефона хранится минимально (HMAC), токен в БД только как SHA-256. Если MAX ещё не позволяет отправить сообщение пользователю по этому номеру — предложить директору переслать ссылку-приглашение, НЕ раскрывающую доступ без проверки телефона.
4. Бухгалтер входит через MAX. MAX Mini App initData криптографически подтверждает MAX user_id, но НЕ номер телефона. Номер проверяется отдельно через MAX request_contact / поддерживаемый signed contact proof, при возможности сверяется с номером профиля; нельзя доверять номеру, просто введённому пользователем. Документация: https://dev.max.ru/docs/webapps/validation и https://dev.max.ru/docs-api/methods/POST/messages .
5. Только при совпадении номера подтверждённого в MAX, действительном приглашении, активном директоре и осознанном подтверждении бухгалтером формируется grant (company_id, director_max_id, accountant_max_id, scopes, grant_id, evidence_id, timestamps).
6. В директорском кабинете статус «Бухгалтер подключён», конкретные права и кнопка «Отозвать». В кабинете бухгалтера организация отображается в списке доступных компаний. Для нескольких ООО нужны отдельные приглашения/гранты.
7. Отзыв директором лишает доступа немедленно на серверной стороне, блокируя новые запросы, а не только скрывая кнопку UI. Вести журнал кто/когда/кому назначил, подтвердил, изменил и отозвал права. Изменение состава прав требует повторного подтверждения.
8. При смене руководителя, потере полномочий, смене номера или подозрительной активности доступ может приостанавливаться до повторной проверки.

## Правовые детали
Разрешение в сервисе управляет техническим доступом и должно опираться на достаточное договорное и правовое основание. Не заменяет автоматически доверенность/МЧД для представительства перед госорганами. Внешний бухгалтер подтверждает обязанности конфиденциальности и право использовать сервис; персональные данные обрабатываются на надлежащем основании.

## Реализация-прототип
app/finexpert/delegations.py — автономный Python-модуль реестра приглашений, активных прав и отзыва. tests/test_finexpert_delegations.py — тесты.
Нет публичных API, отправки сообщений в MAX, действующей проверки директора или signed contact, нет выдачи реального доступа. Методы регистрации подтверждённого директора и телефона предназначены ТОЛЬКО для последующих доверенных серверных адаптеров; категорически нельзя оборачивать их открытыми HTTP-ручками.
В дальнейшем — перенос с SQLite на PostgreSQL с миграциями, RBAC/ABAC и антивирусным pipeline для документов, интеграционные испытания MAX, юридическая проверка.

## Критерии приёмки
Положительный сценарий приглашение->подтверждённый контакт->grant; чужой номер, неверный токен, истечение TTL, повторы, чужая компания, неуполномоченный директор, отзыв, одновременные запросы, смена директора, запрет расширения scope.
