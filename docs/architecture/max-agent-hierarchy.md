# MAX — один бот, иерархия агентов и субагентов
Решение пользователя от 2026-11-22. Внутреннее имя главного координатора: «Кирюша». Коммерческие бренды («Ваш Финэксперт» и другие продукты) НЕ обязаны включать «Кирюшу».
Технически MAX поддерживает inline_keyboard, callback-события message_callback и кнопку open_app: https://dev.max.ru/docs-api/use-cases/sending-messages/keyboard/ .

## Утверждаемая модель
Один MAX-бот, единая регистрация/верификация, общий координатор и реестр внутренних AI-агентов. Верхнее меню:
1. Юрист -> договоры, претензии/взыскание, анализ
2. Ваш Финэксперт -> бухгалтерский учёт, Персональный финансовый навигатор, Мои документы
3. Менеджер -> CRM, продажи, задачи
4. Маркетолог -> VK, рекламные кампании, конкуренты
5. IT-разработчик -> программирование, верстка сайтов, тестирование, инфраструктура
6. Преподаватель -> курсы и репетитор
Существующий агент аналитика конкурентов становится субагентом маркетолога; VK SMM — маркетолог; sales — менеджер; tutor — преподаватель. Юрист и разработчик сохраняются. Бухгалтер добавляется как новый агент, управленческий контур — подмодуль бухгалтерского агента, не отдельный агент. Новые категории добавляются декларативно через реестр и UI-конфигурацию.

## Как должен работать callback
POST /messages с attachment inline_keyboard; на нажатие MAX отправляет message_callback. Webhook должен проверить секрет, уникальность события, MAX user_id и авторизацию, затем разрешить только известный callback из реестра, сохранить selected specialist / subroute и ответить на callback через поддерживаемый API /answers. Меню должно иметь «Назад» и «Главное меню». Идемпотентность callback_id и очистка устаревших состояний обязательны. Callback payload содержит только route ID, без ИНН, PII, токенов и секретов. Сверять role/tenant/subscription на backend при КАЖДОЙ операции, не доверять состоянию кнопки.
Сложные рабочие формы, файлы и таблицы открываются кнопкой open_app в MAX Mini App; простые запросы, переключение и диалоги остаются в одном чат-боте. В Mini App отображать ту же иерархию на основе единого каталога.

## Разграничение разработки
app/max_menu.py — чистый прототип каталога кнопок и строгого резолвера. tests/test_max_menu.py — сценарии навигации и ошибочных callback. НЕ подключать автоматически к текущему production webhook без проверки структуры update message_callback, авторизации и итогового ответа /answers.
Существующий app/agents/registry.py содержит 6 агентов. Для новых ролей нужен отдельный переход с миграцией состояний Conversation и тестами обратной совместимости, чтобы работающие команды /agent, голосовые команды и Mini App не сломались.
