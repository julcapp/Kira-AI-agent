# Кирюша: делегирование задач MVP

## Подтверждённое поведение
- В MAX: голосовая фраза с расшифровкой «Кира поручаю: ...» или текст `/delegate описание` создаёт задачу.
- Известные категории выбираются детерминированно: конкуренты, VK/маркетинг, юрист, разработчик, продавец, репетитор. До трёх специалистов; неизвестная тема переходит в `needs_clarification`.
- Отправитель получает идентификатор; `/jobs` и `/job ID` показывают состояние и результат. Другой пользователь не может прочитать поручение по ID.
- MAX Mini App API `POST /api/mini/work/jobs`, `GET /api/mini/work/jobs`, `GET /api/mini/work/jobs/{id}` требует подписанный MAX initData; веб-форма Mini App пока не нарисована.
- Scheduler последовательно забирает задачу, собирает текстовые ответы специалистов и сохраняет единый текст. По окончании создаётся MAX notification. Уведомление содержит ссылку на команду просмотра, не весь отчёт.
- Если провайдер LLM не подключён, задача переходит в `failed`; демотекст не считается результатом.

## Ограничения и требования перед production
1. Это не полноценная интеллектуальная декомпозиция: текущий планировщик — правила по ключевым словам. Каждый агент получает общий текст, а итог — объединённые ответы без отдельной независимой QA-проверки.
2. Никакого выполнения внешних действий, публикаций, платежей, удаления и деплоя.
3. Сейчас только **однопроцессный** scheduler; нет production-safe multi-instance leases, recovery зависших jobs, экспоненциальных retry, dead letter и подтверждения доставки exactly-once. MAX уведомления могут продублироваться при аварийном рестарте.
4. Для долговременного хранения требуется применить обе миграции `20261122_01` и `20261122_02` после резервирования базы и тестовой репетиции. В production не применять без отдельного разрешения.
5. Дополнительно требуются независимый контроль фактов, полная трассировка источников, согласования опасных действий, тарификация и ограничения затрат, UI списка задач, вложения и экспорт файлов.
6. Требуется автоматическое восстановление незавершённых jobs после перезапуска и верификация реальной доставки уведомления.
7. Набор исполнителей из PR #3 («Автор статей») доступен только после интеграции этой ветки; здесь используются шесть исходных агентов.
