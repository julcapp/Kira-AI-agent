# Единый MAX-бот: шесть направлений и расширяемый каталог субагентов через CRM
Дата решения: 2026-11-22. Проектная модель и изолированный прототип, **не реализованная CRM**.
Основной бот/внутренний координатор: «Кирюша». Публичный финансовый сервис: «Ваш Финэксперт»; управленческий модуль: «Персональный финансовый навигатор».

## Структура
Шесть верхних разделов: (1) Юрист, (2) Ваш Финэксперт, (3) Менеджер, (4) Маркетолог, (5) IT-разработчик, (6) Преподаватель. Внутри — сколько потребуется вложенных категорий/субагентов, с техническими квотами на глубину, размер меню, нагрузку и лимиты MAX.
Существующие реализации: lawyer, developer, sales, vk, competitors, tutor; accountant — планируемый агент. Новые субагенты могут переиспользовать существующий движок/промпт либо требовать нового исполнительного инструмента: создание записи в CRM само по себе не создаёт исполняемый код/интеграцию.

## CRM — реестр
Поля category/agent: id(uuid), key, parent_id, title, description, icon, sort_order, enabled, stage(draft/test/published/archived), visibility, route_name, instructions_version, default_model, allowed_tools, required_role, required_plan, max_depth, quota, language, created_by, updated_by, published_by, version, published_at.
Отдельно хранить конфигурацию инструментов, разрешения по организациям, платные тарифные функции, журнал изменений и версии настроек.
Изменения конфигурации: создать черновик -> валидировать -> preview -> тесты на известных запросах и callback -> утверждение уполномоченным администратором -> публикация атомарной версии -> журнал -> откат.
Планируется в PostgreSQL + API; в текущем MVP БД SQLite и отсутствует полноценная CRM/tenant isolation — НЕ считать имеющийся код безопасной промышленной реализацией.

## Навигация
inline_keyboard в MAX для выбора раздела и подагента; callback payload содержит безопасный ключ маршрута, НЕ параметры авторизации, телефон, ИНН, секреты и документы; callback server-side проверяется по текущей опубликованной версии каталога.
Кнопки «Назад», «Главное меню», «Мои задачи», «На моё решение», «Открыть Mini App».
Mini App отображает тот же опубликованный каталог, с фильтрацией по роли и тарифу и повторной авторизацией каждого действия на сервере. Подбор специалиста по тексту и голосу остаётся альтернативой кнопкам.
Если нет доступа по роли/тарифу: показать корректное объяснение, но не выполнять операцию.

## Оркестрация и человеческие решения
Каждый агент анализирует и выдаёт рекомендации, но не принимает финальное решение за пользователя. Отдельный human-in-the-loop согласующий workflow обязателен перед межагентной передачей и любым внешним юридически значимым действием (публикация, платёж, отправка претензии, отчётности, изменение данных, deploy).
Центральный координатор сохраняет case_id, источник, версии документов, целевого агента, разрешения, статусы и результат. Запрещён автоматический доступ к чужим организациям.

## Изолированный прототип
app/agent_catalog.py и tests/test_agent_catalog.py — декларативный каталог шести разделов, расширяемых вложенных элементов, тесты на ограничение маршрутов/отключённые записи. Данные статичны, нет CRUD-API, отсутствует настоящая CRM и backend webhook-интеграция; без подтверждённой проверки MAX callback и прав не подключать к production.
Соседний app/max_menu.py — ранний статический прототип inline-клавиатуры; в дальнейшем оставить один источник данных (CRM-каталог), исключив две несовместимые модели.
При развертывании в первую очередь обеспечить: PostgreSQL миграции, верификацию MAX, RBAC/ABAC, подписки, логи, тестиpование и CI, согласование merge.
