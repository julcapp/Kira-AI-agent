# Daily News — Кирюша

Статус: техническое задание, без активации рассылки и без изменений production.

## Основные сценарии
Команда `/daily_news` впервые запускает онбординг по 6 последовательным вопросам. Для настроенного пользователя показывает выпуск по запросу; расписание доставляет выпуск после отдельного согласия пользователя.

Шаги:
1. `city_preference` — город/регион или общая повестка.
2. `topics` — массив: технологии, бизнес/экономика, политика, спорт, наука, культура, IT/стартапы, крипто, городские новости.
3. `sources` — необязательные RSS/сайты и разрешённые Telegram-источники.
4. `delivery_time` — HH:MM (09:00 по умолчанию) и `timezone` — IANA часовой пояс пользователя.
5. `news_count` — 3, 5, 7, 10; по умолчанию 5.
6. `news_language` — ru/en.

Команды: `/daily_news`, `/daily_news settings`, `/daily_news pause`, `/daily_news resume`. Обратная связь «больше X», «меньше Y», «игнорируй Z», «фокус на X» меняет только персональные веса тем.

## Архитектура
* Таблицы: news_profiles(owner_id, channel, step, config_json, timezone, enabled, updated_at); news_deliveries(owner_id, subscription_id, local_date, status, attempt_count, sent_at) с уникальностью для защиты от дублей; news_feedback; news_seen_articles.
* Источники: RSS/Atom и лицензированные новостные API; поиск как дополнительный адаптер. Каналы Telegram — только через авторизованные поддерживаемые интерфейсы.
* Сбор: 3–5 поисковых направлений по выбранным темам. Даты, первоисточники, несколько независимых подтверждений, регион и язык учитываются при ранжировании.
* Качество: дедупликация ссылок и сюжетов между выпусками, проверка актуальности, отсутствие выдуманных источников, обязательная прямая ссылка для каждого материала.
* Защита: лимиты сетевых запросов и длины текста, защита от SSRF при пользовательских URL, недоверенные инструкции в контенте источников игнорируются, аудит предпочтений без секретов.
* Расписание: отдельный worker, атомарная аренда задачи и outbox; расчёт времени в timezone пользователя с учётом DST, хранение UTC. Обычный `scheduler_loop` из MVP пока только для напоминаний; его нельзя просто дублировать на нескольких репликах.
* Доставка: канал, принадлежащий авторизованному пользователю; первичная настройка без автоматической отправки до подтверждения подписки.

## Проверки перед релизом
1. Шесть шагов, продолжение незавершённой настройки, корректность предпочтений и изоляция пользователей.
2. Ручной выпуск: N уникальных новостей, существующие ссылки, актуальные даты, приоритет проверенных источников.
3. Повторная отправка, рестарт worker, параллельные worker, DST, пауза/возобновление.
4. Ошибки RSS/API, запрет приватных адресов, ограничение запросов, инъекции через статьи.
5. Интеграционные тесты в staging MAX; позднее Telegram, Web и Mini App. Production только после согласования.

## Итерации
1. Модели данных, онбординг и тесты.
2. Конвейер RSS/API + фильтрация, ранжирование и ссылки.
3. Сервис расписания/outbox + отправка MAX.
4. Экран настроек Mini App; Telegram и корпоративные подписки.
