# Состояние проекта — 27.11.2026

Сводка последнего подтверждённого состояния по результатам предыдущих сеансов, не новый аудит.

## Подтверждено
- Jarvis: Ubuntu VM Hyper-V; целевой переход на bare metal Ubuntu по стандарту V2P.
- Docker Engine и Compose установлены; приложение запущено, порт 8000 доступен только локально; /health вернул status ok, mode local; /app HTTP 200.
- 19/19 автоматизированных тестов прошли в отдельном контейнере с тестовой БД. /api/chat и /api/mini/records без авторизации вернули 401.
- SQLite: создана консистентная локальная резервная копия, integrity_check ok. Полная проверка восстановления и независимое резервирование ещё не реализованы.
- Docker, containerd, SSH и безусловный автозапуск VM настроены; испытание полной перезагрузкой не проводилось.
- SSH по ключу через внутренний NAT подтверждён; sudo требует пароль. Публичный интерфейс UP, настроена policy routing, но внешний SSH и исходящий HTTPS через публичный интерфейс не подтверждены.
- На Home-Boss установлены Playwright и Chromium. Действующий прокси Aeza проверен, отдельное подключение Jarvis не создано.

## Решения
- Единая ветка main, единый оркестратор, реестр агентов, библиотека SKILL.md, TimoUI, API/CRM/MCP; расширяемый состав специалистов. Дополнительные агенты не считаются реализованными автоматически.
- Целевой доменный контур unovus.ru: jarvis для администрирования, kiryusha для AI Office, edu для образовательных сервисов. DNS у Hostland; переключение после подтверждения маршрута. Реальные адреса и секреты держать вне публичного Git.
- Aeza — заменяемый поставщик VPS; Gateway Manager с логическим именем шлюза, проверкой нового endpoint и откатом. Не направлять весь трафик хоста через туннель по умолчанию.
- Bare Metal Ubuntu — целевая платформа; чистая установка и восстановление, независимый экспорт VM, проверенные бэкапы всех гостевых машин перед переиспользованием физического хоста.
- Backup, Migration, Recovery, Monitoring и Deployment — единый инфраструктурный контур; см. INFRASTRUCTURE_MIGRATION_STANDARD.md.

## Очередь работ
P0: независимые зашифрованные резервные копии и тест восстановления; безопасный административный доступ; диагностика публичного маршрута.
P1: защищённый заменяемый шлюз при необходимости; DNS, HTTPS и авторизация; PostgreSQL; MAX webhook, Mini App и LLM/TTS/STT, контроль интеграционных тестов.
P2: расширение реестра агентов, образовательный сервис, автоматизированный комплект V2P и нагрузочные испытания.

Не подтверждены: публичный HTTPS, DNS-переключение, новая связь Jarvis–Aeza, live MAX/LLM/TTS, PostgreSQL, полное резервирование и миграция. Не открывать production до проверки авторизации и TLS.

## Обязательный регламент ведения состояния проекта
PROJECT_STATUS.md — канонический источник текущего состояния для ChatGPT, Codex и агентов разработки. Перед работой читать актуальную версию main и сверять фактическое состояние среды. После существенного этапа обновлять подтверждённые результаты, принятые решения, тесты, блокеры и следующий шаг; указывать дату, ссылки на коммиты и проверяемые свидетельства без секретов. Не отмечать планы как выполненные. Исторические ТЗ не перезаписывать. Изменения кода проходят соответствующие тесты перед интеграцией в main и deployment. При расхождении документа с реальной средой сначала проверять факты, затем исправлять статус. Не публиковать закрытые эксплуатационные данные. Обновление статуса не является подтверждением production deployment.
